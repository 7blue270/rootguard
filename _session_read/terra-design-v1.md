## 0. 先校正三件事（从你的数据和图里读出来的）

**(0.1) 你的数据形态决定了问题形状。**
`ANEMIA.json` 里一个 session 是「实验室批次更新 3 个根（hb/hct/rbc）→ 派生查询（mcv/mch/mchc/anemia_class）→ 再一批次…」交替，T≈20+。这意味着：

> **查询是免费的（后处理），预算只花在"刷新"上。**

于是整个问题塌缩成一个纯粹的**刷新调度问题**：给定 T 轮、总预算 B，选「何时刷、刷哪些、各花多少」。这比 RootGuard 的"一次性分配"多两个自由度，也正好是你说的"有限轮次 + 预算有界"。

**(0.2) 图 1D 里 170% 的偏差不是噪声，是"部分刷新破坏了抵消"。**
`mchc = 100·hb/hct`，`mcv = 10·hct/rbc`，`mch = 10·hb/rbc`——全是**比值**。MIMIC 的化验批次里 hb 和 hct 是同向共动的，所以：
- 两个根都漂了，但**比值几乎没变** → 任务没变；
- 你只刷新了其中一个 → 比值被"修"坏了 → **误差反而变大**。

这条比"要不要更新"重要得多：**刷新本身可以是负收益的**。你的三个模板（FIB-4、HOMA、BMI）也是同样的单体式结构，所以这不是 ANEMIA 的特例。

**(0.3) 图 2 的"DP 阈值检测器作用很小且浪费预算"不是实现问题，是 DP 放错了位置。**
你把预算花在"判断要不要刷"上；但判断的结果只影响**怎么刷**。正确的做法是：把这次刷新本来就要花的 `ε_r` 切一小块 `ε_a` 出来，用它**私下地决定这一块预算怎么分**。总花费不变，却买到了自适应。

## 1. 决策变量：从「根变没变」换成「任务漂没漂」

### 1.1 任务在 log 空间是线性的

8 个模板几乎全是**单体式** `T = c·∏ x_i^{a_i}`：

| 模板 | 任务 | 弹性向量 a |
|---|---|---|
| MCV | `10·hct/rbc` | (+1, −1) |
| MCH | `10·hb/rbc` | (+1, −1) |
| MCHC | `100·hb/hct` | (+1, −1) |
| FIB-4 | `age·AST/(PLT·√ALT)` | (+1, +1, −1, −0.5) |
| HOMA-IR | `glu·ins/405` | (+1, +1) |
| TYG | `ln(tg·glu/2)` | (+1, +1) |
| AIP | `log10(tg/hdl)` | (+1, −1) |
| NLR | `neu/lym` | (+1, −1) |
| BMI / conicity | `w/h²`、`waist/√(w·h)` | (+1, −2) / (+1, −0.5, +0.5) |
| MAP | `(sbp+2dbp)/3` | 线性（非单体，但同样可投影） |
| anemia_class / risk | 阈值判定 | **不连续，用"边界余量"** |

于是（一阶）：

```
Δlog T  =  Σ_i a_i · Δlog x_i  =:  δ        ← 任务漂移，客户端零成本可算
```

- **抵消**：`δ ≈ 0` 而各 `|Δlog x_i|` 很大 → 不刷（刷了是纯损失）；
- **放大**：`|δ|` 大 → 刷，且只刷对 `δ` 贡献大的根；
- **单根主导**：`δ` 由某一项主导 → 只刷那个根。

> 一句话：**k 维的"谁变了"问题，投影成一维的"任务漂了多少"问题。**
> 这就是你图 1「属性变化 ≠ 任务变化」的精确版本，也是整篇论文的题眼。

### 1.2 阈值型任务（anemia_class）：换成"边界余量"

`class = 0 if mchc<32 else (2 if mchc>36 else 1)`。这里没有梯度，但有**余量**：

```
m = distance( T(x),  decision boundary )
```
- `m ≫ σ`：类别稳，不刷；
- `m ≲ σ`：类别可能翻转，**必须刷**（哪怕根值只动了一点）。
- 这正好对应你的 `Recall@1` 指标：**Recall@1 掉，等价于余量被噪声吃掉**。

所以两类任务用两套触发量，但共用同一个预算账本。这也解释了为什么你的 Recall@1 对刷新噪声这么敏感。

## 2. 四条可证的结论（论文的"骨架"）

### L1 抵消引理（部分刷新会更差）★ 最适合当"反直觉卖点"

设组 `G` 满足 `Σ_{i∈G} a_i Δlog x_i = 0`（完全抵消）。若只刷新 `i0 ∈ G` 且刷新是准确的，则任务估计改变 `a_{i0}·Δlog x_{i0} ≠ 0`，**任务误差从 0 变成 |a_{i0}Δlog x_{i0}|**。
⇒ **刷新的最小单位必须是"任务相关闭包"（AST 子树覆盖的根集合），要么整组刷，要么不刷。**

这条直接解释你 Fig.1D 的 47%→170% 那组柱子，也是审稿人一眼能记住的结论。

### L2 广义幂律分配（把 RootGuard 收成特例）★ 理论贡献

最小化任务误差的 p 次幂 `Σ w_i (c_i/ε_i)^p`，约束 `Σε_i = E`，得：

```
ε_i  ∝  ( w_i · c_i^p )^{ 1/(p+1) }
```

| 取法 | 结果 | 含义 |
|---|---|---|
| p=1, c=D（域宽）, w=\|a\| | `ε_i ∝ √(\|a_i\|·D_i)` | **RootGuard 的 √ 律**（他们的特例） |
| p=2, c=D | `ε_i ∝ (\|a_i\|·D_i²)^{1/3}` | 平方误差下的静态最优 |
| p=2, c=\|Δlog x_i\| | `ε_i ∝ \|a_i\|^{1/3}·\|Δ_i\|^{2/3}` | **漂移感知最优（本文）** |

记忆点：**弹性给 1/3，漂移给 2/3**。
直观：`a_i` 大的根对任务影响大，要多给；`Δ_i` 大的根"欠账"多，更要给——而且欠账按 2/3 次方给，比线性更激进（因为噪声是平方进误差的）。

> 论文里这一节写成：*RootGuard 是 p=1、c=D、m=1 的退化情形；我们给出完整的三维族谱（p, c, m）。* 这是最省力的"差异化叙事"。

### L3 增量发布 vs 重锚：主导关系 ★ 直接打你"刷新噪声是瓶颈"的观察

刷新一个根有两种写法，**同样的 ε，误差差一个量级**：

| 方式 | 发布 | 噪声尺度 | 绝对误差 |
|---|---|---|---|
| **重锚**（RootGuard 式重发） | `x̂' = x' + Lap(D/ε)` | `D/ε` | `D/ε` |
| **增量**（本文） | `x̂' = x̂ + Lap(\|Δ\|/ε)`，`Δ = x'−x` | `\|Δ\|/ε` | `√(σ₀² + (Δ/ε)²) ≈ σ₀` |

因为 `|Δ| ≪ D`（一次化验的波动远小于生理值域），**增量发布在同等预算下把误差压回初始锚点水平**。
代价：增量误差会随刷新次数累积（随机游走），所以需要一个**切换规则**：

```
if |Δ| < γ·D :  增量发布（便宜、保持连续）
else          :  重锚（贵，但清空累积误差）
```
`γ` 由预算和漂移率决定，可解析（见 L4 的 λ）。

> 这条同时解决你图 2 观察到的两个现象：刷新噪声大、以及"更新且保留旧值"那根柱子为什么偏低（它本质上就是增量）。

### L4 时机：均匀 epoch 是最优的，而且**没有调度信道** ★ 系统 DP 的关键

若漂移是平稳随机游走（每轮 log 漂移方差 v），把 m 次刷新均匀铺在 T 轮上，任务误差的时间积分最小（标准的 AoI/采样定理结论）。
更重要的是：**epoch 时刻是公开的、与数据无关的** → 不存在"刷新时刻泄漏"的信道。

于是整个机制变成：

```
公开的：T, m, epoch 时刻, 预算 B
私有的：每次 epoch 内部怎么切预算、刷哪些根
```

> **时机公开（可证无信道）+ 分配私有（有自适应收益）**，这是本文在 DP 侧最干净的一句话。
> 若你将来想做自适应 epoch，就必须上 privacy filter（Rogers et al. 2016），复杂度陡增——现在这版不需要，对 CCF-B/C 刚好。

## 3. 机制：TERRA（Task-Elasticity Refresh with Randomized Allocation）

### 3.1 骨架

```
输入: T 轮, 总预算 B, 刷新次数 m, 网格 A, 切分比 ρ∈(0,1)
epoch 时刻: τ_j = j·T/m           # 公开
每轮 t:
  ├─ 查询请求 → 直接返回 f(x̂_cache)         # 后处理，零成本
  └─ 若 t == τ_j:                          # 刷新 epoch
       1. 客户端读干净值 x(t)，算 Δlog x 与 δ = Σ a_i Δlog x_i   # 免费
       2. 若 |δ| < θ_task: 跳过（省下的预算滚入下一次）           # 任务没漂，不刷
       3. 否则：
          a. 在公开网格 A 上用指数机制选分配 α ∈ A
             效用 u(α) = − E[任务误差² | α]
             隐私成本 ε_a = ρ·ε_r
          b. 按 α 切分 (1−ρ)·ε_r 给各根，逐根增量/重锚发布
             隐私成本 ε_v = (1−ρ)·ε_r
          c. 组原子性：若某闭包内多个根都超阈值，整组一起刷
```

### 3.2 预算账本（必须能一眼算清）

```
单次 epoch:  ε_r = ε_a + ε_v = ρ·ε_r + (1−ρ)·ε_r
总预算:      Σ_j ε_r,j  ≤  B                （跳过时结余，不许超支）
隐私保证:    B-组合（basic composition），epoch 之间全部是后处理
调度信道:    无（epoch 公开；"跳过"不改变发布内容，只改变预算余额——余额不可观测）
```

### 3.3 为什么分配要用指数机制（而不是直接用 Δ 定噪声尺度）

**这是一个真正的坑**：如果令 `ε_i ∝ |a_i|^{1/3}|Δ_i|^{2/3}`，那噪声尺度 `σ_i = c_i/ε_i` 就是**私有数据的函数**。
数据依赖的噪声尺度**不自动满足 DP**——对手可以从多次发布的离散度反推 `σ_i`，进而反推 `Δ_i`。

两种正解：
1. **指数机制**（推荐）：从**公开网格** `A` 里选分配，效用含 `Δ`，成本 `ε_a`，标准保证 `ε_a`-DP + 效用损失 ≤ `2Δu/ε_a`；
2. **平滑敏感度**（smooth sensitivity，Nissim et al. 2007）：直接用 `Δ` 定尺度，但要加一个平滑上界，效用更好、实现更重。

> 这也回答了你原来的思路：**"阈值判断"本身不该被 privatize（那是在浪费预算），该被 privatize 的是"分配"**——而它本来就在你这次刷新的预算里。

## 6. 风险与 Plan B

| 风险 | 概率 | 应对 |
|---|---|---|
| L2/L3 被认为是"工程调参" | 中 | 把 L1（负收益）提到主贡献；L2/L3 作为"因此需要新分配规则"的推论 |
| 增量发布的 DP 语义被质疑（metric DP 的 δ-不可区分） | 中 | 明确定义：**更新幅度不可区分性**，并给出与值级 DP 的关系定理 |
| ANEMIA 太简单（3 根、比值） | 中 | 加 FIB-4（4 根、含 sqrt）与 conicity（3 根、非线性）；MIMIC 真实队列兜底 |
| 指数机制的网格太粗，收益被吃掉 | 低 | 网格用"预算分配比例"而非绝对值；ρ 扫描给出最优 |
| 审稿人要"下界" | 中 | 可给：任何数据无关调度 + 任意分配的最小最大误差下界（AoI 风格） |

**Plan B（如果 L1 被抢发）**：转向"阈值型任务的边界余量刷新"，即用分类 margin 而非梯度做决策，配 Recall@1 的理论刻画。这条线目前没人做。
