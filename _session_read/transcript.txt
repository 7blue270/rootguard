## 我目前理解到的内容

**RootGuard**（arXiv:2605.03188v3）的核心表述是：根节点**只加噪一次**，之后所有发布都是 `f(x̂)` 的确定性后处理，因此隐私只取决于初始消毒，与对手选择什么函数、问多少轮无关；总预算 `B = t·ε` 按 `ε_i ∝ √(|h_i|·D_i)` 分配到各根。

这套结论**完全建立在“根不变”之上**。你的场景正好针对这一点：把根看成**分段常值过程** `s_i(t)`，于是：

> 隐私成本的真实驱动量，从“轮数 t”变成“状态迁移次数 m + 迁移幅度 |Δ|”；而 RootGuard 的“双重不对称”（轮数越多越好）会在这里**反转**——轮数多往往意味着更新多，对“重加噪”来说是成本（`m·ε`），对“不刷新”来说是陈旧。

## 一、你的决策变量选错了（这是好消息）

你现在的隐含决策量是「**根变没变**」。但 ANEMIA 里 `mchc=100·hb/hct`、`mcv=10·hct/rbc`、`mch=10·hb/rbc` **全是比值**，而 MIMIC 化验批次里 hb 和 hct 是同向共动的。于是：

- 两个根都变了 → **比值几乎没变 → 任务没变**；
- 你只刷了其中一个 → **比值被“修”坏了 → 误差反而变大**。

这就是你 Fig.1D 里那组一百多的偏差、以及“属性变化不一定意味着任务变化”的真正机理——它不是数据噪声，是**部分刷新破坏了抵消**。这个现象在 RootGuard 框架里根本不存在（它不刷新），所以它是你的**反直觉卖点**，不是 bug。

正确的决策量是一维的：

```
δ = Σ a_i · Δlog x_i        （a_i 是任务对第 i 个根的弹性）
```

因为 8 个模板几乎全是单体式 `T = c·∏x_i^{a_i}`（FIB-4 含 √、BMI 含平方、HOMA 是乘积），log 空间里任务对根是**线性**的。于是 k 维的“谁变了”投影成一维的“任务漂了多少”：`δ≈0` 不刷（刷了是纯损失），`|δ|` 大才刷，且只刷对 δ 贡献大的根。阈值型任务（`anemia_class`）换成**边界余量** `margin`——这也正好对应你的 `Recall@1`。

## 二、图 2 已经否掉了“DP 阈值检测器”，但否掉的不是这个想法，是它的位置

你的观察“DP 阈值检测器作用很小且浪费预算”——完全正确，而且原因很硬：

> 判断的结果只影响**怎么刷**。你把预算花在“要不要刷”上，等于为一个不影响发布内容的决定付费。

正确的位置是：**把这次刷新本来就要花的 `ε_r` 切出 `ρ·ε_r`，用它私下地决定这一块预算怎么分**。总花费不变，却买到了自适应。形式上用**指数机制**（公开网格 + 效用 = 负任务误差），而不是 LDP 协议——LDP-IDS/MTSP-LDP 那类是为“不可信收集者 + 频次估计”设计的，和你的场景（客户端可信、数值、敏感度已知）不同构。这个“DP 放在分配里而不是判断里”本身就是一条可写进论文的机制洞察。

顺带一个**必须避开的坑**（系统 DP 的经典陷阱）：如果直接令 `ε_i ∝ |Δ_i|^{2/3}`，噪声尺度就是私有数据的函数，**不自动满足 DP**——对手能从多次发布的离散度反推尺度、再反推 Δ。所以要么指数机制（推荐），要么平滑敏感度。

## 三、四条可证的骨架（够 CCF-B/C）

| | 结论 | 作用 |
|---|---|---|
| **L1 抵消引理** | 组内 `Σa_iΔlog x_i=0` 时，只刷一个根会把任务误差从 0 变成 `\|a_iΔlog x_i\|` | 反直觉主结果，解释你的 Fig.1D |
| **L2 广义幂律** | 最小化 `Σw_i(c_i/ε_i)^p` ⇒ `ε_i ∝ (w_i c_i^p)^{1/(p+1)}`；p=1,c=D 就是 **RootGuard 的 √律**，p=2,c=\|Δ\| 得 `ε_i ∝ \|a_i\|^{1/3}\|Δ_i\|^{2/3}` | 把 RootGuard 收成特例，最省力的差异化 |
| **L3 增量 vs 重锚** | 小幅漂移用增量发布（噪声尺度 `\|Δ\|/ε` 而非 `D/ε`），绝对误差压回锚点水平 | 直接治你“刷新噪声是瓶颈”的观察 |
| **L4 时机** | 平稳漂移下均匀 epoch 最优，且**时刻公开 ⇒ 无调度信道** | 解释“周期基线很强”，并把 DP 侧做干净 |

**L4 是这篇文章的结构性洞见**：时机是无聊的（公开、均匀、可证无信道），战场全在“怎么分”。你之前纠结的 w-event 之所以走不通，正是因为它把保护对象绑在窗口上，而固定 B 下窗口被迫等于 T——你转向有限流是对的。

## 四、一个必须回你的事实

你图 2 说“简单周期基线已有很强竞争力”——这不是坏消息，这恰恰是 L4 的**实验预演**：它说明时机不是瓶颈。所以你的 money plot 不该是“我的调度更聪明”，而该是：**同预算下，公开周期 + 漂移感知分配 vs 公开周期 + 均匀分配**。前者赢，收益就纯粹来自 L2/L3，审稿人无话可说。

## 一、为什么“目标抵消”不等于“不用刷”

你的数据里，`mcv / mch / mchc` **本身就是被查询的节点**，`anemia_class` 只是末端。所以：

- hb、hct 同比漂移 → `mchc=100·hb/hct` **不变**（目标抵消），但 `mcv=10·hct/rbc`、`mch=10·hb/rbc` **都变了**；
- 服务方下一轮问的恰恰是 mcv/mch——你返回旧值，就是**答错**。

所以“抵消”是**逐节点**的，不是全局的。你的决策量“根值变化对任务的影响”是对的，但**“任务”必须定义成 workload（被查询节点集合 + 查询频率），而不是单一 target**。这正是你担心的“两个都变得够大，中间结果也变了”——它在框架里不需要特判，自动成立。

精确形式是一个 k×k 的半正定矩阵：

```
M = Σ_j w_j · a_j a_jᵀ        a_j = ∂log T_j/∂log x_i（AST 符号求导）
J(S,ε) = b_Sᵀ M b_S + Σ_{i∈S} (c_i/ε_i)² M_ii
         └ 陈旧偏置 ┘   └ 新噪声方差 ┘
```

**`M` 的对角线就是 RootGuard 的敏感度，非对角线就是“抵消/放大”本身**——RootGuard 只用了对角线，所以它在多根同时漂移时必然做错决定。这句话基本可以当论文的 related work 分水岭。

`a_mcv=(0,1,−1)`、`a_mch=(1,0,−1)`、`a_mchc=(1,−1,0)`，取 `w=(0.3,0.25,0.3,0.15)`：

```
M = [[ 0.55, -0.30, -0.25],
     [-0.30,  0.60, -0.30],
     [-0.25, -0.30,  0.55]]
```

| 漂移 | `J(∅)` | 决策 |
|---|---|---|
| Δ=(δ,δ,0)（hb/hct 同比，rbc 不动） | `0.55δ² > 0` | **要刷**（mcv/mch 变了） |
| 同上，但 workload 里只有 anemia_class | `≈0` | **不刷**（真抵消） |
| Δ=(δ,δ,δ)（三根同比） | `0` | **不刷**（所有比值不变） |
| Δ=(δ,δ,1.2δ) | `>0` | 要刷，且只刷 rbc 性价比最高 |

同一漂移、不同 workload，结论相反——**这就是为什么“是否更新”既不能只看根，也不能只看 target**。

## 三、阈值：其实不需要阈值了

给定 S，预算分配仍有闭式解（还是那个“弹性 1/3、漂移 2/3”）：

```
ε_i = E · (M_ii c_i²)^{1/3} / Σ_l (M_ll c_l²)^{1/3}
J(S) = b_Sᵀ M b_S + (Σ_{i∈S} (M_ii c_i²)^{1/3})³ / E²
```

而 `k ≤ 6`（ANEMIA=3，FIB-4=4），`2^k = 8~64`，**直接穷举**：

```
S* = argmin_S J(S)   s.t.  J(∅) − J(S) > λ·E     (λ = 预算影子价格)
```

**阈值不是被删掉，是被 `J` 的等值面替代了。** 在 k=2 的漂移平面上，决策区是一条**围绕“补偿方向”的带状区**，外面才是刷新区——任何标量阈值 `|Δ|>θ` 都切不出这个形状。这大概也是你之前阈值实验“效果有限”的理论解释：用一维阈值去拟合二维楔形区，必然有系统性 regret。

## 四、检测要不要花隐私预算：判据只有一句

> **决定是否改变“发布值的分布”，而它又依赖私有数据 → 必须计价；否则不用。**

- 「刷 / 不刷」改变分布，由私有 Δ 决定 → 要计价，**但二值判断信息量太低，买了也白买**（这正是你图 2 测到的）；
- 「选哪个 S + 怎么切」候选空间大得多 → 同样 `ρ` 买到的东西多得多。

而且 `ε_a` **从这次刷新本来就要花的 `ε_r` 里切**，不是额外开销：

```
ε_r = ε_a + ε_v = ρ·ε_r + (1−ρ)·ε_r      方差 ×1/(1−ρ)², 典型 ρ = 0.05–0.15
```

这里有个必须踩住的坑：**数据依赖的噪声尺度不自动满足 DP**。若直接令 `ε_i ∝ (M_ii Δ_i²)^{1/3}`，`σ_i` 就成了 `Δ_i` 的函数，对手能从多次发布的离散度反推它。所以只能走“公开网格 + 指数机制”或“平滑敏感度”。这一步不做，整套机制在理论上不成立——也是审稿人最容易一剑封喉的地方。
