# 隐私模型架构 v1

**固定会话预算 · 有界漂移的轨迹 DP**

> 状态：设计稿，未实现、未实验。目的：把"预算模型、DP 定义、账本、机制骨架、历史记录的地位"一次定死，避免后面返工。
> 前序：`framework-v2-workload-ast.md`（从会话归档恢复，见 `_session_read/`）。本文修正它的三处不严谨：噪声尺度、账本结转、支持集泄漏。

---

## 0. 先给三个结论

1. **预算用会话级固定 B**，不随轮数 T 增长；RootGuard 的 `B = t·ε` 只作为第二个 regime 做对照。
2. **DP 保护的对象是整段根轨迹**，不是"每次发布单独保护"；查询是后处理，成本恒为 0。
3. **时序公开、值和切分私有**：刷新时刻是公开日程（无时刻信道），私有的只有"值"和"这一轮预算怎么切"，切分用指数机制从本轮预算里切 ρ。

一句话的机制观：**"要不要更新"不再是一个需要决策的动作。**每轮都发布带噪增量，真值为 0 时发布的就是纯噪声，缓存自然被"复用"；真正需要花隐私预算的只有"哪些根这次值得发布"，而它由指数机制承担。

---

## 1. 场景与信任边界

- 客户端可信（用户设备上的 agent），服务端不可信（LLM 服务/被注入的 agent），与 RootGuard 相同。
- T 轮有限会话；每轮服务端可能查询**任意派生节点**，包括中间节点（MCV/MCH/MCHC），不只末端任务。
- 根的新值来自检验批次（更新可以是 1 根、2 根或整批 3 根），更新时刻公开。
- 服务端能看到：每一次发布的数值、提问顺序、提问时刻、公式、取值域、epoch 日程。
- **用户自己报出的中间值（如"我的 mcv 是 98"）不进入状态**（本轮确认）。它最多作为一致性提示，不改变缓存、不触发刷新。好处：状态更新只来自可信测量，不存在"用户文本污染状态"这条额外的数据依赖分支。

## 2. 公开 / 私有

| 信息 | 归属 | 说明 |
|---|---|---|
| T、epoch 时刻、刷新周期 | 公开 | 时刻公开 ⇒ 无时刻信道 |
| 公式 / AST / 依赖图 | 公开 | 服务端本来就知道它要算什么 |
| 取值域 `[lo, hi]`、漂移界 `C_i` | 公开 | 模型假设，见 §3 |
| 总预算 B、网格 𝒜、ρ | 公开 | 公开参数 |
| 查询日志（哪些节点被问、几次） | 公开 | 服务端自己问的 ⇒ workload 权重 `w_j` 公开 |
| **根的值 `x_i(t)`、增量 `Δ_i(t)`** | **私有** | 唯一的私有对象 |
| **本轮刷新集合 S 与预算切分 α** | **私有** | 由指数机制从公开网格选出，计 `ε_a` |

一个关键观察：**`M = Σ_j w_j a_j a_jᵀ` 是公开的。** 公式公开、弹性 `a_j` 由 AST 符号求导得到、权重 `w_j` 来自公开查询日志——所以"任务结构"不花一分隐私预算，花预算的只有"值"。这让整套账本非常干净：DP 只关于 Δ，不关于 M。

## 3. DP 定义

### 3.1 归一化与模型假设

```
z_i(t) = (x_i(t) − lo_i) / (hi_i − lo_i)  ∈ [0,1]
```

**假设 A-drift（有界漂移，公开）**：相邻两个测量点之间 `|z_i(t) − z_i(t−1)| ≤ C_i`。
`C_i` 取临床可解释的公开上界（例如"两次化验之间不超过域宽的 5%~10%"），**必须在真实 MIMIC 数据上报告违反率**；违反时机制裁剪（引入有界偏差），并在公开日程的锚点处清零。

### 3.2 相邻关系

两条轨迹相邻：它们在**一个 epoch 的某一根**上相差不超过 `C_i`（事件级相邻），其余完全相同。

- 用事件级而不是 `d_∞`：`d_∞` 会让增量的敏感度变成 `2C_i`（两个端点都可能动），把便宜的优势吃掉一半。
- 不用 w-event：w-event 假设"事件流已给定"，而我们的"事件"（哪根变了、变多少）本身是私有的。这是本文与 w-event 的分水岭，也是 related work 的对话点。

### 3.3 保证

**定义（transcript DP）**：机制 `M` 作用于整段轨迹，输出整段会话的全部发布。若对所有相邻 `X, X'` 与所有输出集合 `S`，

```
Pr[M(X) ∈ S] ≤ e^ε · Pr[M(X') ∈ S] + δ,   ε ≤ B
```

则称该会话满足 `(ε, δ)`-DP。查询（含自适应查询）全部是已发布值的后处理，成本为 0。

### 3.4 敏感度表（这是全篇的地基）

| 发布内容 | 敏感度（归一化） | 噪声尺度 | 备注 |
|---|---:|---|---|
| 锚点 `x_i(τ)` | `1` | `1/ε_i` | 全域名宽，贵，只在锚点 epoch 付 |
| 增量 `clip(Δ_i, C_i)`（跨 g 个 epoch） | `min(g·C_i, 1)` | `s_i/ε_i` | 便宜，主力 |
| 预算切分 α（指数机制） | — | — | 成本 `ε_a = ρ·ε_e` |

> **必须钉死的一句话**：噪声尺度只能用**公开**的 `s_i`，绝不能用私有的 `|Δ_i|`。`σ_i ∝ |Δ_i|` 不满足 DP——对手可以从多次发布的离散度反推 `σ_i`，再反推 `Δ_i`。"小变化便宜"必须来自**公开的漂移界 C**，不能来自**私有的变化量**。这是本文在系统 DP 上最硬的一条，也是审稿人最容易一剑封喉的地方。

## 4. 预算模型（重点）

### 4.1 预算是什么

ε 不是"钱"，是**隐私损失的刻度**：机制对相邻输入的输出分布的对数比上界。ε 越小越私密、噪声越大。总预算 B 是整段会话允许的累计损失上限。组合定理保证：多次发布的总损失 ≈ 各自 ε 之和（basic）或更紧的界（advanced / RDP）。

### 4.2 RootGuard 的 `B = t·ε`

他们的建模是："对手逼出 t 轮交互，用户在每一轮'获得' ε 的额度，总损失 t·ε。"
- 后果：会话越长，隐私越弱，但**每次发布的噪声不变**。
- 好处：长对话的效用不会崩。
- 代价：隐私随轮数线性变差；而且"因为 T 大所以刷新更多"变成免费，正好把我们要研究的"更新要花钱"抹掉了。

### 4.3 固定会话预算 B

"这段会话总共就这么多隐私，怎么花你决定。"
- 每次发布的额度 = `B / m`（m = 公开的刷新次数）。
- 后果：刷新越多，每次噪声越大；刷新越少，缓存越陈旧。
- 好处：**更新真的要花钱**，`(m/T, B)` 相图才有意义；审稿人也不会问"为什么对手多问几轮你的隐私预算反而变多"。

### 4.4 为什么选固定 B（四条）

1. **语义正确**：隐私是用户的资源，不该由对手的提问次数决定。
2. **科学问题成立**：只有固定 B，"刷新频率 vs 噪声 vs 陈旧"才是真权衡；否则最优解永远是"每轮都刷"。
3. **能解释你的实验**：Fig.2 里刷新噪声压垮效用，恰恰是固定 B 下的必然现象——这不是实现问题，是预算模型问题。
4. **可写进论文**：固定 B + 公开日程 + 显式账本，是一段干净的、可被审稿人检查的论证。

### 4.5 账本怎么记

```
总预算：      Σ_{epoch} ε_e  ≤  B           （m 公开 ⇒ 组合次数公开）
单 epoch：    ε_e = ε_a + ε_v = ρ·ε_e + (1−ρ)·ε_e
              ε_a：指数机制选 (S, α)
              ε_v：本轮发布（Σ_{i∈S} ε_i = ε_v）
查询：        0（后处理）
```

**保守约定**：每个 epoch 无论输出什么，都记满 `ε_e`。这样组合次数恒为 m、账本确定。若 S=∅ 时不想白付 `ε_v`，就必须上 privacy filter（Rogers et al. 2016），复杂度上升——CCF-B 版先不用。

### 4.6 与 RootGuard 的连接

保留 `B = β·T` 作为第二个 regime（"额度随轮数增长"），在同一张图上画两条曲线。论文的叙事就变成：**RootGuard 的结论只在 `B ∝ T` 且根不变时成立；固定 B 且根会变时，结论反转。** 这比"我们比 RootGuard 好"高级得多，也不容易被说成调参。

## 5. 机制骨架

公开参数：`T, m, epoch 时刻, 锚点周期 P, C_i, 域, 网格 𝒜, B, ρ`。

每个 epoch `τ_j`：

```
1. 客户端读当前干净值，算 Δ_i = log x_i(τ_j) − log x_i(τ_{j−1})     # 本地，免费
2. 指数机制在公开网格 𝒜 上选 (S, α)，效用 u(S,α) = −J(S,α; Δ)       # 花 ε_a
   J(S,α) = b_Sᵀ M b_S + Σ_{i∈S} (s_i/ε_i)² M_ii
3. 对 i ∈ S 发布：
     锚点 epoch： r_i = x_i + Lap(s_i/ε_i),  s_i = 1
     增量 epoch： r_i = r_i^prev + clip(Δ_i, C_i) + Lap(s_i/ε_i),  s_i = min(g·C_i, 1)
4. 其余根复用缓存（不发布）
5. 记账：ε_e 扣减，Σ ≤ B
```

三档对照（也是消融）：

| 档 | 分配怎么定 | 隐私成本 | 作用 |
|---|---|---|---|
| A | RootGuard 静态 M-Roots | 一次性 | 基线 |
| B | 公开闭式 `ε_i ∝ (M_ii s_i²)^{1/3}` | 0（公开） | 证明"框架本身"有价值 |
| C | 指数机制自适应（用私有 Δ） | `ρ·ε_e` | 证明"自适应"额外有价值 |

`s_i` 公开 ⇒ 闭式分配也是公开的，不花预算；指数机制买的是"按**真实**漂移调整"的能力。`ρ→0` 必须退化成 B 档——这是一条硬性 sanity check。

## 6. 四个陷阱

1. **数据依赖噪声尺度**：`σ ∝ |Δ|` 不是 DP。用公开 `C_i` + 裁剪，绝不条件化在私有量上。
2. **账本结转泄漏**：省下的预算若让下一轮噪声变小，则"省不省"这个私有决定从噪声尺度泄漏出去。要么不结转，要么上 filter。
3. **支持集泄漏**：S=∅ 与 S={i} 在观测上不同。把 S 放进指数机制的输出空间，让泄漏被 `ε_a` 覆盖。
4. **时刻信道**：任何由私有 Δ 决定的"何时刷"都会泄漏 `|Δ|>θ` 这一谓词。用公开日程，彻底关掉这条信道。

## 7. 历史记录：能提供什么

### 7.1 对手侧（威胁面）

1. **平均攻击**：同一底层值被独立加噪发布 q 次，对手取平均，方差降为 1/q。组合定理已覆盖（q 次就是 q·ε），但**效用评估**必须用"会平均的对手"。
2. **时间相关先验**：Kalman 平滑 / 变点检测。DP 对任意先验成立，所以保证不受影响；但**经验攻击**必须用它，否则是稻草人（这是 F5）。
3. **公式一致性**：从多个派生值反解根。历史越长，可解的方程越多——RootGuard RQ1 的对抗查询正是这条。
4. **查询模式 → workload**：对手知道哪些节点重要，就能定向攻击。注意这同时是我们的资产（M 公开）。
5. **稳定期证据**：连续多轮值不变，本身就是"没更新"的证据。
6. **身份链接**：跨模板的同一患者（你的数据里 25 位患者跨 4 个模板）。

### 7.2 客户端侧（资产）

1. 精确 `Δ`、漂移率、变点 → 但**用于调度就产生信道**（§6.4）。
2. workload 统计 → `M`（公开）。
3. 锚点与累计误差 → 决定何时重锚（若日程公开，则不用私有数据）。
4. 重复/自适应查询免费（后处理）。

### 7.3 文献现状

- **RootGuard**（[arXiv:2605.03188](https://arxiv.org/abs/2605.03188)）：缓存 + 后处理，多轮查询免费；但根不变。
- **持续观测 / 流式 DP**（[Dwork et al., STOC 2010](https://dl.acm.org/doi/10.1145/1806689.1806787)；Chan–Shi–Song 2010；Kellaris et al. w-event, VLDB 2014）：发布时刻固定，或事件流已给定；不处理"事件判定"。
- **隐私滤子 / 组合**（[Rogers–Roth–Ullman–Vadhan, NeurIPS 2016](https://proceedings.neurips.cc/paper_files/paper/2016/hash/58c54802a9fb9526cd0923353a34a7ae-Abstract.html)）：m 随机时的正确工具。
- **DP3**（[ACL Findings 2026](https://aclanthology.org/2026.findings-acl.924/)）：多轮文本 DP，指出"重复 token 反复消耗预算"，用扰动映射表复用、两阶段分桶指数机制。**这是与我们最接近的"多轮复用"工作**，但对象是 token、没有数值更新语义，也没有"更新 vs 复用"的效用权衡。
- **Prεεmpt**（[arXiv:2504.05147](https://arxiv.org/abs/2504.05147)）、DP-Rewrite、InferDPT、AdaDPS：逐轮文本改写，预算按轮消耗。
- **PrivacyBench**（[arXiv:2512.24848](https://arxiv.org/abs/2512.24848)）：多轮 RAG 助手泄露率最高 26.56%，说明历史本身就是泄露面。
- **RAPPOR**（[CCS 2014](https://research.google/pubs/rappor-randomized-aggregatable-privacy-preserving-ordinal-response/)）：永久随机响应 / 记忆化的先例。

**结论**：多轮 DP 的主流是"逐轮消耗 + 复用减少重复消耗"；**没有人把"根级数值状态更新 + 稀疏刷新 + 有界漂移"放在同一个账本里**。这就是空位。

### 7.4 我们的机制覆盖了什么

| 多轮要素 | 状态 | 说明 |
|---|---|---|
| 重复/自适应查询 | ✅ 覆盖 | 后处理，0 成本 |
| 状态演化（根更新） | ✅ 覆盖 | 版本化缓存 + 公开 epoch |
| 历史相关决策 | ✅ 覆盖 | 唯一私有决策走指数机制，计 `ε_a` |
| 历史作为辅助信息 | ✅ 覆盖（保证）/ ⚠️ 待做（评估） | DP 对任意 side info 成立；但实验要加会利用历史的对手 |
| 跨会话（下次再来） | ❌ 未覆盖 | 需要账户级预算，另算 |
| 用户明文自报中间值 | ✅ 已排除 | 不入状态 |
| 服务器主动探测 | ✅ 覆盖 | 自适应查询是后处理 |
| 时序网络侧信道 | ⚠️ 假设 | 日程公开 ⇒ 时刻不携带额外信息 |

## 8. 要证的命题

- **P1（组合）**：上述机制满足 `(B, δ)`-DP；查询全部是后处理；账本不超支。
- **P2（分配）**：给定公开 `s_i` 与 `M`，闭式 `ε_i ∝ (M_ii s_i²)^{1/3}` 最小化 `J`；RootGuard 的 √律是 `s_i = D_i, p=1` 的退化特例。
- **P3（周期）**：在 A-drift + 随机游走漂移下，最优锚点周期 `P*` 有闭式/半闭式解，且随 `C/D` 单调。
- **P4（边界）**：`m/T → 1` 时缓存范式失效，RootGuard 严格劣于逐轮发布——把原论文的结论推成边界条件。
- **P5（经验）**：在历史感知对手（平均 + Kalman + 变点）下，机制仍保持优于静态缓存与周期重锚的效用。

## 10. CCF-B 定位

- 不宣称"首次提出多轮 DP"；定位为：**静态缓存范式的失效边界 + 有界漂移下的任务感知重发布机制**。
- 三个贡献点：① 固定 B 下的 `(m/T, B)` 相图与失效边界（P4）；② 有界漂移的增量发布 + 公开日程的无信道论证（P1/P3）；③ 任务弹性加权的预算分配（P2），把 RootGuard 收成特例。
- 审稿人必问：与 w-event 的区别（事件私有 vs 事件给定）；与 DP3 的区别（数值状态 vs token）；威胁模型（客户端可信、日程公开）；为什么固定 B（§4.4）；A-drift 是否现实（报违反率）。
